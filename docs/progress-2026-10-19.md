## Changes in this branch

WaitSynchronization1 now obtains its 64-bit timeout from r2/r3, matching the
actual ARM veneers (e.g. 0x0012160C..0x00121614 and 0x0030310C..0x00303124).
The former r1/r2 decode included unrelated/stale r1 values in timeouts.

Thread-handle waits now validate the target; a live target with zero timeout
returns timeout. A main-thread join pumps the scheduler until the target exits
or the deadline expires, rather than immediately returning success. Worker
joins carry finite deadlines, return timeout on deadline wake and success on
termination wake.

A native ARM fixture creates a child, polls it with timeout zero while r1 holds
junk, then joins it infinitely. It checks a memory marker written by the child
before ExitThread, so a spurious successful join cannot pass the test.

Validation: 34 Rust tests, two native PICA tests under ASan/UBSan, release build,
and git diff whitespace checks passed. The real generated game runner was
built separately as `/tmp/dq8-worker-fix`, leaving the agent's target binary
untouched. A bounded real-raster run reached 614 draws and 420 transfers and
then a pending-state poll; no title screen is established by that run.

## Descriptor investigation

Write tracing at 0x08653280..0x08653294 found:

- 0x001316B4/0x001316C4 construct a valid descriptor (0x004D6594,
  0x004D6548, 0x002774AC, 0x08653298).
- The constructor at 0x001B70BC/0x001B70C4/0x001B70CC overwrites those words
  while constructing an adjacent job object at 0x08653268.
- 0x001B7838 and 0x001B7860 write task-result/state bytes at +6/+5 of its
  owner, producing 0x248 inside the descriptor's entry word in the old run.
- Captured thread stack tops 0x08653280 and 0x08653250 are close enough that
  lifecycle, ownership and scheduling must be resolved before assuming valid
  independent stacks. No descriptor bytes or guest return values are patched.

The wait fixes change the subsequent execution, but the real runner still
polls a pending object near 0x0024F7A0. Resolving stack/descriptor lifetime and
the responsible worker/queue is the next work. A dispatch-at-CreateThread
experiment exists only under `/tmp`; it is not a production change.

Some CPU-only diagnostic runners suppress raster work explicitly to make
allocator/thread tracing faster. They cannot establish visual correctness;
real-raster runs are reported separately.
